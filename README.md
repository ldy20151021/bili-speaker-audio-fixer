## 这是解决什么问题的？

用猫抓（或其他下载工具）从 B 站抓下来的音频，通常是 `m4s` 或 `mp4` 后缀，很多人会**直接把后缀改成 `.mp3`**。

然后就会发现：

| 场景 | 结果 |
|------|------|
| Windows 自带播放器 / PotPlayer | ✅ 能播 |
| 手机 / 电脑音乐软件 | ✅ 能播 |
| **音响 / TF 卡 / 车载** | ❌ **放不出来** |

**原因**：改后缀只是换了个"马甲"，文件里装的仍然是 **AAC 编码 + MP4 容器**。电脑和手机是软件解码，什么都能解；而音响是**硬件解码芯片**，芯片里没烧 AAC 解码器，直接跳过不读。

本工具帮你把文件**真正转码成标准 MP3**，并针对老音响的解码芯片做了一系列兼容性调整。

---

## 功能

- **体检模式**：只读不改动，扫描出每个文件的真实编码、时长、采样率，以及是否存在隐患，输出 CSV 报告
- **去垃圾头**：部分缓存文件开头被塞了无用字节，导致连 `ffprobe` 都读不出来——自动识别并跳过
- **重封装 M4A**：只换容器不改音频流，**音质零损失**
- **转码 MP3**：调用 LAME 编码器真正重新编码
- **音响专用模式**：192k CBR / 44.1kHz / 立体声 / ID3v2.3 / Xing 头，兼容性拉满
- **自动摊平编号**：输出成 `001_曲名.mp3`，摊平到一个文件夹（老音响扫不到多层子目录）
- **清理文件名**：自动去掉 `BV号`、`av号`、`P01`、`audio` 等噪音，写入歌曲标题标签
- **剥离视频轨**：只保留声音
- **重建时长索引**：修复 DASH 分片时长缺失、进度条拖不动的问题

## 前置依赖

需要 **FFmpeg + FFprobe**（本工具不含，需自己装）：

```powershell
winget install Gyan.FFmpeg
```

> ⚠️ 装完后**必须重新开一个窗口**，否则 PATH 不生效。
> 验证：输入 `ffmpeg -version` 有输出即成功。

## 快速开始

1. 下载本仓库全部文件，和你的音乐文件放在**同一个文件夹**
2. 双击 `1_check.bat` 先体检一遍（可选，但推荐）
3. 双击 `4_to_speaker_mp3.bat`，等它跑完
4. 把生成的 `音响专用` 文件夹里的 mp3，拷到 TF 卡**根目录**

**四个 bat 的分工：**

| 文件 | 作用 | 适用场景 |
|------|------|----------|
| `1_check.bat` | 体检，只读 | 先看一眼心里有数 |
| `2_to_m4a.bat` | 重封装 `.m4a` | 手机 / 电脑 / 网易云，音质零损失 |
| `3_to_mp3.bat` | 转码 `.mp3` 320k | 剪辑 / 老设备 |
| `4_to_speaker_mp3.bat` | **音响专用** `.mp3` | **音响 / TF卡 / 车载 ← 多数人选这个** |

输出结果默认放在 `已修复` 或 `音响专用` 子文件夹，**不会动你的原文件**。

## 高级用法

直接在 PowerShell 里调用，可以传更多参数：

```powershell
# 音响模式，码率改成 256k
.\BiliAudioFixer.ps1 -Mode SPK -Bitrate 256k

# 文件名只保留序号（音响挑食中文名时用）
.\BiliAudioFixer.ps1 -Mode SPK -ShortName

# 处理别的目录
.\BiliAudioFixer.ps1 -Mode SPK -Dir "D:\我的音乐"

# 原地输出，不建子文件夹
.\BiliAudioFixer.ps1 -Mode M4A -InPlace
```

**参数说明：**

| 参数 | 说明 |
|------|------|
| `-Mode` | `Check` / `M4A` / `MP3` / `SPK` |
| `-Dir` | 工作目录，默认脚本所在目录 |
| `-Bitrate` | 码率，如 `192k` `256k` `320k`。默认 MP3=320k，SPK=192k |
| `-Flatten` | 摊平到一个文件夹并编号（SPK 模式默认开启） |
| `-ShortName` | 文件名只保留 `001.mp3` 这样的序号 |
| `-InPlace` | 原地输出，不建子文件夹 |

## 拷到 TF 卡后还是放不了？按顺序排查

1. **TF 卡文件系统** — 64G 以上的卡出厂默认 **exFAT**，绝大多数便宜音响只认 **FAT32**。在电脑上重新格式化成 FAT32（32G 的卡一般出厂就是 FAT32）
2. **放根目录** — 别套多层文件夹，mp3 直接拷到卡的第一层
3. **文件名** — 中文名放不了、英文名能放，说明音响不支持中文编码，用 `-ShortName` 改成纯数字文件名
4. **别超 999 首** — 老音响的索引上限，超出了后面的扫不到
5. **安全弹出** — 拷完用「安全删除硬件」弹出，直接拔容易写坏 FAT 表

## 为什么音响认不出改后缀的"MP3"？

简单说几个关键点：

- **编码格式**：MP3 是 MPEG-1/2 Layer III，AAC 是 MPEG-4 的编码，两者完全不同，音响芯片里烧什么解码器就只能解什么
- **采样率**：B 站音频经常是 **48kHz**，而很多廉价 MP3 解码芯片只支持 **44.1kHz**，48k 会直接哑掉或放成噪音
- **码率模式**：VBR（动态码率）老芯片算不准，工具统一用 **CBR**（固定码率）
- **ID3 标签**：ID3v2.4 有些老设备解析会卡死，工具统一写 **v2.3**
- **时长索引**：DASH 分片的 moov 头常常不完整，需要重写才能正确显示时长、拖进度条

## 常见问题

**Q: 双击 bat 闪一下就没了？**
A: FFmpeg 没装好，或者装完没重开窗口。PowerShell 里输入 `ffmpeg -version` 验证。

**Q: 提示"读不出来，文件已损坏"？**
A: 下载时缓存不完整，重新下一次。

**Q: 速度慢吗？**
A: M4A 模式是纯复制，几百个文件几十秒。MP3 是真转码，一首大概几秒，几百首可能要十几分钟。

**Q: 音质会损失吗？**
A: M4A 模式零损失。MP3 模式会有损失（AAC → MP3 是二次有损编码），所以音响没需求的话优先用 M4A。

**Q: 支持批量子文件夹吗？**
A: 支持，会递归扫描。SPK 模式下会统一摊平编号。
